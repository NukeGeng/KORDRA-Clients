# FEAT-CLIENTS-WEBSITE-001 — Public KORDRA website

## Ownership and scope

The owner assigned the public KORDRA website to the KORDRA-Clients repository at `website/`. The owning module is **Clients / Public Website**. This is a presentation and editorial responsibility, not a KORDRA Product business module. Product remains authoritative for product behavior, permissions, tenant boundaries and API contracts.

The website explains KORDRA's purpose, product direction, current development status, public documentation and published updates. It implements an approved Orbital Control / Engineering Editorial design as a native WordPress Block Theme. The scope covers Home, Features, Documentation, Blog / Updates and Releases / Download views.

Out of scope: operational Control Plane UI, Product API clients, authentication, tenant data, invented product capability, live telemetry, company infrastructure details, product backend changes and routine production WordPress deployment. A one-time public theme publication is allowed only by explicit website-owner instruction and must be recorded with the deployed artifact and actual verification.

## Use cases, actors and authorization

- **Primary actor:** anonymous public visitor who wants to understand KORDRA, inspect its roadmap and status, read public documentation or updates, and determine whether a real release exists.
- **Editorial actor:** a WordPress editor who manages published pages and posts through WordPress's existing capabilities. This feature adds no custom roles, permission checks or login flow.
- **Tenant scope:** not applicable. Public pages contain no tenant-specific data and accept no tenant identifiers.
- **Visitor permission:** read published public content. Drafts and WordPress administration remain protected by WordPress core.
- **Product authorization:** none is performed by the theme. Product permissions remain server-owned; the site makes no API calls.

## Current motion direction — GSAP homepage scroll choreography

Theme 0.2.19 uses the already-vendored GSAP 3.15.0 core and IntersectionObserver to reveal homepage targets as they enter the viewport. Scroll events also reconcile target geometry so a fast jump cannot leave currently visible content hidden when an observer entry is skipped. If scrolling carries an entering target fully offscreen, its work is canceled and the visible queue is rescheduled in DOM order without stale wait time. Each release step animates its circular marker, then its label and description; the step completes in about 260 ms, and the next starts after 280 ms, left-to-right on desktop and top-to-bottom on mobile. While any reveal is entering, vertical wheel/trackpad input is paced to 72% and capped at 180px per event; this does not lock the page or pace idle input. Touch, keyboard and horizontal scrolling, browser zoom, an open mobile menu and reduced-motion mode remain native. The Foundation paragraph completes before the repository action begins. The topology's radial connections and satellite dots share the same scroll-linked rotation; their four labels follow the same positions while their text stays horizontal. The dashed orbit advances and concentric rings scale subtly; there is no continuous background orbit loop.

Partial exits never erase completed content; full viewport exits reset targets, and returning to them replays the reveal without inheriting a stale queue delay. Motion pauses while the document is hidden, keyboard focus immediately exposes its target, and reduced motion or missing GSAP/IntersectionObserver leaves content readable. Wheel pacing is limited to active reveals and does not take over section progression. Teardown and script reinitialization clear tweens, styles, observers and listeners. The home reveal script depends on the existing GSAP asset; no new package, ScrollTrigger plugin, Product contract, tenant scope or ADR is introduced.

The typewriter acceptance and verification notes below are historical; this owner-requested direction supersedes glyph clipping and per-character timing.

## Historical animation correction — DEF-WEBSITE-MOTION-001

The CSS 0.2.4 percentage ranges do not satisfy the accepted interaction. Scroll distance both advanced and erased text, different element heights produced different timing, and multiline blocks were clipped across several lines at once. Prior computed-style snapshots did not prove the complete scrolling interaction.

The following typewriter behavior was the accepted correction at the time. It is historical and superseded by the GSAP scroll choreography above:

- One visible item types at a time in document reading order: headline rows, support copy, release nodes from left to right (top to bottom on mobile), then actions.
- Within wrapped copy, finish each rendered line from left to right before beginning the next. Preserve the original semantic text and layout; no character-span rewriting or screen-reader duplication.
- Entry runs on elapsed time. Stopping at the page end still completes the Foundation paragraph before the repository action. Long text blocks finish within 600 ms, with a short 20 ms gap between items. The first release/status headline row uses the primary white at weight 700; only its secondary row uses muted gray.
- Typed content remains visible while any part of its target remains in the viewport. There is no scroll-driven exit eraser. Natural viewport clipping removes upper rows first when scrolling down and lower content first when scrolling up.
- Reset only after a target is completely outside the viewport; returning from either direction repeats the entry. Fast scrolling cancels offscreen work and prioritizes the currently visible reading order.
- Resize/font changes remeasure the text without truncating completed content. Keyboard focus immediately reveals its target and preceding visible copy. Reduced motion, missing script/APIs and a controller failure leave all content readable.

Historical implementation decision: native browser scheduling and text-range measurements replaced independent CSS view timelines. The prior scroll-reveal controller used timed opacity and vertical translation without measuring or rewriting text; theme 0.2.16 now uses the existing GSAP core for that choreography. Tests map `assets/js/reveal.js` to `website/tests/reveal.test.cjs`; runtime/browser checks remain separate from static checks.
